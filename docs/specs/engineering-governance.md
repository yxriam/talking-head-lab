## 输入/输出契约

输入为实际 AGENTS.md、PROJECT.md、CLAUDE.md、账号规格、历史变更记录、package.json、现有忽略文件，以及只读 Git/工具盘点结果。输出为以下允许改动清单：

- `AGENTS.md`、`CLAUDE.md`、`PROJECT.md`：保持既有产品决策，新增治理入口和真实状态。
- `.cursor/rules/project.mdc`：使用官方 MDC frontmatter（alwaysApply），只要求读取同一规范，不复制完整规范。
- `docs/WORKFLOW.md`：从规格到发布、部署验证和回退的具体操作，以及 Git 缺失分支。
- `docs/templates/task-spec.md`、`docs/templates/change-record.md`：需求契约、责任、失败证据、阶段状态及回退占位。
- `.github/pull_request_template.md`：供未来有效仓库使用的最小检查表；不声称已在远端启用。
- `.gitignore`：凭据、模型、环境、缓存、生成媒体、采集与本机工具产物；保留源码、公共网页资源、规格、文本记录和脱敏示例。
- 本规格、本轮记录、修改前清单/快照、统一 diff 和校验输出。证据文件不含用户原始媒体或凭据。

|---|---|---|
| G0 冻结规格与基线 | 已完整读取相关文件；根与子仓库、身份及未提交状态有记录；快照在修改前保存 | 无 |

| G2 发布边界与忽略 | 用 Git 原生匹配验证代表路径：敏感/生成产物忽略，源码/规格/示例/网页公共资源保留 | G0 |
| G3 审查与交付 | 本轮实际统一 diff 经逐项自查；引用有效；既有文件、子仓库状态保留；真实发布缺口与回退可用 | G1、G2 |
| G4 GitHub 发布 | 根有效仓库及远端可用后，显式暂存本任务文件，审 staged diff，提交并确认远端提交号 | 用户解决根仓库归属；本会话不可假造通过 |

G0至G3构成一个独立文档/config任务，未来可作为一个小提交。G4因 Git 无效待用户决定；本地验收完成后不自动展开业务实现。

| 编号 | 验收用例 | 通过标准 |
|---|---|---|
| AC01 | 规则一致 | CLAUDE/Cursor 指向 AGENTS/PROJECT/任务规格；AGENTS 原规则完整保留 |
| AC02 | 引用与技术事实 | 本轮本地 Markdown 链接有效；Node >=22.13.0 与 package.json 对齐；官方 Cursor 格式可追溯 |

只运行文档引用/规则一致性、Git 忽略匹配、快照/diff/逆向恢复检查。业务文件未改，不运行 GPU、整站 build 或后端模型测试。Git 忽略验证可只读借用子仓库 Git 元数据并指定根 work-tree；这仅验证规则，不代表根仓库恢复，也不修改子仓库 index/历史。
