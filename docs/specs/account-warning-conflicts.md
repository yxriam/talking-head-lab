# 账号反诈警示：重大矛盾的证据与时间规格

- 版本：1.0，2026-10-08（工作记录日期采用 Pacific/Auckland）。
- 来源：用户在当前会话明确提出的产品要求。
- 状态：需求已确认；本轮只更新记录和工作规范，功能实现与新模型验收待完成。

## 需求与优先级

默认用户提供的信息是真实事实。仅在材料内部出现明确相反的说法，或防范声明与实际行为明显不一致时，分析该不一致；不能用通用真实性免责声明代替分析。

当两条不一致直接影响付款、验证码、身份核验、账户控制或联系渠道，并有具体证据说明影响重大时，将该防范控制缺口作为当前最优先处理的薄弱环节。不能将它扩大成“这个人容易被骗”、性格缺陷或受骗概率，也不能把所有细节差异都排成最高优先级。

必须同时呈现：

1. 第一条原文、证据编号、原有来源链接，以及其时间。
2. 第二条原文、证据编号、原有来源链接，以及其时间。
3. 具体冲突点：同一主体、同一事项的哪两项说法不能协调，或哪项已宣称的防范动作与所述行为不一致。
4. 防范影响：这项不一致会使哪一步核验失效，以及草稿支持的条件性后果。
5. 立即核验或修复的动作，与该缺口对应。

不能只输出“资料有矛盾”“信息不代表身份”“不代表真的认识家人”或“提高警惕”。现有“知道家事不能确认新联系者身份”的一般提醒也不能充当矛盾证据。重大矛盾出现时先列证据与时间，再说明影响。

## 时间与事实约束

- 发布时间、资料中明确写出的事件时间分别保留，不互相替代。
- 原资料缺时间，写“时间未提供”；没有事件时间，写“事件时间未提供”。不得补造时间、推断近期或把采集时间当事件时间。
- 保留时间原文和原有精度。没有时区，不擅自补时区。
- 不同时间的说法可能是状态变化。材料已明确说明变更、学习过程或更换联系方式时，按有据的变化处理，不机械宣布矛盾。
- 时间不同不能自动消除重要防范不一致。例如，较早发布的付款规则与较后发布的站外转账自述需要并列时间与证据，分析要求和执行之间的缺口；没有事件时间时，不能仅按发布顺序认定行为先后或适用同一规则时期。
- “不太熟悉技术，但会用邮箱”可以同时成立，不属于矛盾。Ray 现有材料没有提供重大防范矛盾，不得为贴合规格伪造第二条证据。
- 对事实是否相冲突、时间关系、对防范动作是否重要分别判断。现有单个 conflict 布尔值不足以完成这些要求。

## 输出契约

外层保留现有双语正文与证据编号格式。中英文引用逐字保留原文语言，翻译或转述不能伪装成原文引语。正文必须让读者直接找到两条陈述及各自时间；来源编号与链接在已有记录中可追溯。

内部需能追溯到一对真实来源及各自时间，不能仅根据模型的“有矛盾”标签生成警示。具体内部字段和优先级实现方式在实现任务的规格中明确；不得悄悄改变现有 API 或页面结构。

### 验收示意（人工构造，不是 Ray 的事实）

> E1，发布时间 2026-09-10；规则生效时间为原文明示的 2026-09-10：原文“自2026-09-10起，所有付款都必须在原平台内完成”。
> E2，发布时间 2026-10-01；事件时间为原文明示的 2026-09-30：原文“2026-09-30，我没有独立核实，就先向新提供的个人收款账户转账”。
> 薄弱环节是付款前的渠道与收款方核验：原先的防范要求与后来的操作不一致。若继续未核实就付款，钱可能继续付给错误的收款人。先停止追加付款，从原平台独立核实收款方，并确认当前执行的付款规则。

示意日期与陈述仅用于合成验收用例，禁止带入真实人物报告。

## 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC01 | 用户资料一致 | 接受事实，不默认质疑真实性或真实亲属关系 |
| AC02 | Ray 的技术描述 | “不太熟悉技术”和“会用邮箱”不判矛盾，不补出薄弱人格 |
| AC03 | 同一事项有重大防范不一致，双方都有时间 | 输出双方原文、各自时间、来源、具体缺口、条件性后果、对应动作；重大缺口排在普通信息暴露前 |
| AC04 | 一方或双方缺时间 | 对应位置明确“时间未提供”，无新增日期 |
| AC05 | 发布时间与事件时间不同 | 两种时间分别保留，不能混用 |
| AC06 | 不同时间有明确变化解释 | 按变化处理，不机械判断矛盾，不无据排成最薄弱环节 |
| AC07 | 细节差异不影响防范动作 | 不升级为重大防范缺口，不推断容易被骗 |
| AC08 | 只有一个来源或没有可核对的相反陈述 | 不生成第二条证据；不得只凭 conflict=true 写重大警示 |
| AC09 | 正常业务邮箱、无风险材料 | 不套用亲属、付款或验证码场景 |
| AC10 | 双语及原文引用 | 中英等义、引用原文不改写、两端引用同一证据对与时间 |
| AC11 | 重大矛盾正文 | 不能用“不代表”等概括判断替代两条陈述、时间和影响 |
| AC12 | 后果与边界 | 不造已发生损失、诈骗话术、攻击步骤、人物弱点或概率 |

程序测试与模型实跑分别留证据。规则测试通过不代表 Qwen 内容通过；一个挑选出的好回答不代表多样例稳定通过。每次改提示词前冻结输入、验收条件、参数与停止条件，改动后保存实际输出和失败原因。
