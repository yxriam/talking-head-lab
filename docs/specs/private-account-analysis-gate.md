## 目标、边界与契约

先使用可见文字与已有用途规则判断私人/企业或机构/无法确定。只对已判为私人账号的材料运行风险规则与Qwen；企业/机构和无法确定仅返回双语类型、依据与跳过原因。Public/Friends是可见性，不是账号用途；公开创作者不能直接当企业，也不能直接当私人。

沿用现有分类规则及原始证据，不按Ray姓名、路径或邮箱分类，不新增身份认证/受骗画像。私人/企业混合用途或单一不足标签保持无法确定。本轮实现调用门控，不声称分类器能准确覆盖所有账号。

允许：account_risk、account_llm、crawl_server、通用评测入口、模型角色前提、相关测试与文档。保留生成API的草稿执行器契约；其原始输入没有整账号材料，分类位于采集/桥接上游。网页风险生成入口必须经过分类；底层generate不承担用途识别。不改页面、模型、部署或发布。

外层旧report字段保留，增加analysis_scope={target:'personal', account_kind:'personal'|'business'|'undetermined', eligible:bool, reason:str}。非私人报告 rows/priorities/protections/subjects为空，narrative及narrative_en只含类型说明，generation.kind='classification'；不能称LLM失败或生成了诈骗风险。刷新返回200类型结果，不依赖GPU在线。旧报告缺门控字段时桥接按account_purpose重新作门控，不让旧风险正文绕过。

## 验收矩阵

| 编号 | 场景 | 通过条件 |
|---|---|---|
| S01 | 明确私人用途、普通个人资料 | eligible=true，既有风险整理与模型接口仍可用 |
| S02 | 明确企业用途，即使有家庭或付款内容 | 不运行风险规则/模型；双语企业类型与依据，风险字段为空 |
| S03 | 信息不足或混合用途 | 不假定私人；返回无法确定与跳过原因 |
| S04 | Public/Friends/创作者标签 | 不以可见性或创作者标签直接判企业/私人；保留类别依据 |
| S05 | 旧报告没有analysis_scope或携带旧风险 | 桥接独立检查用途，不调用GPU，不保留非私人风险段 |
| S06 | 任意用例名称/路径 | 分类只来自输入用途证据，没有人物专用分支 |
| S07 | 实際Ray资料 | 由同一分类规则判私人；可运行，但不能把旧内容失败当质量通过 |
| S08 | 采集与刷新接口 | 非私人分类结果不报模型离线/回退，无GPU调用；既有导出兼容 |

规则函数的低层测试继续检查证据与风险规则本身；另新增产品入口测试，断言非私人连低层分析都不运行。桥接测试的私人前提要在输入明确提供，不能默默假设。
