- 日期：2026-10-09，Pacific/Auckland；版本1.0。
- 来源：用户指出不得针对 Ray 或某个 case 特殊化，要求通用解法。AI中途将“只关注私人”误解为“统一假设私人”；已纠正，最新先分类要求见 private-account-analysis-gate.md。
- 基线：源工作区根 Git 无效；before 快照位于 docs/change-records/2026-10-09-general-warning/。已有发布 checkout 本轮不改动、不推送。

## 目标与边界

本文件保留通用改写的历史实验；当前输入必须先经过私人/企业用途分类，只有私人进入风险生成。将生产提示词改为与人物、亲属关系和风险类型无关的编辑规则；同一生成函数处理所有输入。评测支持外部用例文件或任意采集结果文件，每例实际调用 Qwen，不按案例名称替换答案。

范围：local_account_model.py、account_llm.py 的通用材料准备、通用评测脚本/冻结用例、旧 Ray 评测入口、相关程序测试与记录。保留 account_risk/account_story 的已有通用规则草稿；不把规则提供的后果冒充 Qwen 自行发现。不改 API/页面、模型权重，不微调、不同步服务、不发布。

重大矛盾时间与证据对功能仍按 account-warning-conflicts.md 单独实施；本轮消除提示词中特定亲属示例，不宣称该旧布尔矛盾分支已满足新规格。

约束：默认事实真实，未来风险有条件；只改写已有风险与防范动作。不得生成针对真实人物的诈骗话术、伪造材料、攻击步骤、人物易骗判断或概率。无风险材料只整理事实。资料中嵌入的指令不执行。

## 输入与输出

保留 generate(draft,evidence_ids,root,draft_en=None,facts=None) 和 zh/en → text/evidence_ids。输入中的人物、联系方式和材料决定内容；SYSTEM_PROMPT 不出现 Ray、固定邮箱、特定家庭结构、某个风险类型的完整预制结论。

通用评测 --cases 指定 JSON 用例列表，每条有 name/result/acceptance；或 --result 指定任意采集 JSON。--output 指定本轮结果文件（已存在拒绝覆盖）。name 仅用于报告，不参与生产分支。所有用例走同一规则草稿→generate→桥接验证路径；桥接 mock 仅替代 HTTP 返回，不替代真实 Qwen 生成。

## 冻结验收矩阵

## 实验与停止条件

已有 Qwen3-1.7B Q8_0，llama.cpp CUDA，temp=0，非思考，c=6144，正文 n=1500，矛盾检查 n=80。最多3版通用 SYSTEM_PROMPT；单次只改一个有理由的提示词变量，同一矩阵复跑，失败输出保留，不挑单个好例子作为通用成功。G07/G08 使用单独兼容控制（合计10次每版上限）；Ray 单独回归。参数和用例不随版本改变。

必要验收通过即结束；到达尝试上限仍有失败，明确剩余问题，不声称所有场景通用稳定。不保证仅靠提示词能克服1.7B能力上限。

## 决策与交付

通用化与既有安全/架构边界由用户确定；AI负责实现、有限实验及实际 diff 自查。独立 Claude 审查未授权且本轮不调用。验收后记录程序通过/模型语义通过/未部署各自状态。无有效根 Git 使用 before/after SHA256与统一diff，不初始化、不伪造提交。

经验回写：评测可以有固定测试数据；生产规则不得为其中一例预制人物与风险内容。通用性必须用不同类型及无风险控制验证。

历史实验在第一次推理前把 G05 改成个人联系方式。当时的“统一假设私人”是AI误解；当前以先分类门控规格为准。历史输入保留，不依据新门控伪造已通过模型结果。

## 首轮发现与实现范围补充

v1 原始输出保留在 results-v1.json。除小模型省略动作外，还发现原桥接只引用规则已识别的事实，漏掉普通链接和第二条矛盾事实。增加同一 prepare_material 供生产桥接与评测使用：未进入草稿的原事实按原文引用补入输入，不补风险；沿用12段、3600加权草稿长度、4000事实长度上限。不改外部API、不改时间字段，不声称完成重大矛盾功能。

为区分原因，v2仅修复通用材料准备、保持v1提示词；v3才修改提示词结构要求。原始cases.json与参数不变，最多三个全矩阵轮次，Ray另跑一次。保留v1缺失输入而不是改用例去适应旧规则。
