# 视频使用原图：移除背景替换前置步骤

- 日期：2026-10-09，Pacific/Auckland；版本1.0。
- 需求来源：用户指出README的“项目准备后的肖像”是已经要求去掉的步骤，明确“不需要更换背景”。这一决定覆盖旧运行代码、旧模型演示和README中默认背景生成的前提。
- 当前基线：发布main/44e92f21f29f7709a15eff2391d942add5c93c8d；原工作区server.py和Studio.tsx与发布版本字节一致。背景调用仍在运行链，不能仅删README图片冒充功能已移除。

## 目标、范围与非目标

所有视频模型直接收到用户上传的原图，不执行Qwen场景选择、SDXL生图、U2Net合成或generated-portrait前置。取消背景环境对视频就绪的门控；账号Qwen功能独立保留。前端不再把克隆台词交给背景分类，明确显示原图直达模型。模型自己需要的裁剪、缩放、帧生成和原生构图仍沿用既有实现。

范围：server.py、相关既有测试、Studio.tsx、sync-runtime.sh的必要目录检查、双语README/后端说明/现状/共享规则、修正后的公开合成演示及记录。仅定向同步server.py并重启API以验收实际新流程；不使用全量同步脚本夹带原工作区新的账号提示词/门控实验。

非目标：改变模型、参数、API结构/资源ID/任务队列、删除旧任务/模型权重/历史实验、发布未验收账号业务、外部付费推理或重新跑全部GPU模型。

## 输入与输出契约

- 上传原图字节和驱动音频按现有media_id交接，原图路径在任务request.json和渲染调用中保持一致。
- 视频旧客户端的text字段继续允许（500字符边界不变），但忽略其背景用途；语音任务仍使用text生成音频并返回source_text。
- 视频不创建scene.json、scene-prompt.txt或generated-portrait.png，不调用旧prepare_video_portrait。旧结果的scene字段保留键，当前视频标记为original，不伪称neutral_studio新生图。
- Linux/Windows分工和GPU互斥保留；TokenHub仍在原WSL服务路径执行，仍使用COS临时对象，只把传入图改为原图。
- 视频就绪仅取决于其选定模型/云配置，不再依赖InstantID、场景LLM和背景权重；Qwen账号分析就绪独立。

## 冻结实跑与停止条件

使用README已公开的synthetic-input.png和generated-voice.wav，不重新生成输入或语音，不改模型参数；只改变“移除背景前置”这一变量。新SadTalker最多一次生成、新视频最多一次本地检测，TruthScan关闭，保存新任务ID、耗时、输入SHA256、request和实际输出。旧44e92f2输出保留在Git历史及本机原任务目录，不覆盖成新的成功证据。

代码/程序测试/构建通过后，在API无正在运行任务时只同步server.py，保存运行版本快照、校验SHA256、重启并health确认。若实跑失败保留结果，不换模型或伪造新演示。完成新展示与发布后停止；若浏览器截图工具仍因环境刷新失效，保留事实并寻求明确允许的截图替代，不把旧背景输出截图说成当前流程。
